# Codex 残り使用量 — Windows オーバーレイ

Codex の **5時間枠・7日間枠の残り割合とリセット時刻**を表示する補助アプリです。公式アプリの上に、小さな黒いカードを重ねて表示します。青のアクセント・角丸・透過背景を使っています。

## Windows で使う

1. Node.js 22.12 以上（LTS 推奨）をインストールします。
2. このリポジトリを ZIP で取得し、「すべて展開」します。
3. `start.cmd` をダブルクリックします。初回は必要なパッケージを取得します。
4. Codex CLI に同じ Plus アカウントでログイン済みなら、その認証で取得します。未ログインならパネルの「ログイン」、または通知領域のメニューからブラウザでログインします。

**v0.1 からの移行は一度だけ新しい ZIP が必要です。** 古いパネルの × または通知領域の「終了」で旧版を終了し、v0.2 以降のフォルダの `start.cmd` を起動してください。その後の改善版はアプリが取得します。初回のフォルダは削除・移動せず、以後もその `start.cmd` から起動してください。認証は Codex が管理するため、再ダウンロードしたソースへ認証ファイルをコピーする必要はありません。

PowerShell から起動する場合はプロジェクトのフォルダで実行します。

```powershell
npm.cmd ci
npm.cmd run install:electron
npm.cmd start
```

別 OS の `node_modules` はコピーせず、Windows 側で `npm ci` を実行してください。

## 位置・大きさ・非表示

パネル右上の **⚙** または Windows の通知領域のアイコンを右クリックして設定します。

- **ドラッグ**：ヘッダーをつかんで移動すると自由位置になります。位置は次回起動時にも復元します。
- **表示位置**：画面左下、ChatGPT / Codex の左下への追従、自由位置を選べます。10px 単位で上下左右に調整でき、位置の初期化もできます。
- **複数画面**：表示先の画面を選べます。画面を外した場合は表示できる範囲へ戻します。
- **大きさ**：最小 252×178、コンパクト 292×204（標準）、ゆったり 332×224。以前の 354×260 より小さくしています。
- **最前面**：固定をオン・オフできます。
- **×**：通知領域へ非表示にします。裏で使用量・アプリの更新は続きます。
- **−**：タスクバーへ最小化します。
- **復帰**：通知領域のアイコンをクリックするか、メニューの「表示する」を選びます。最小化はタスクバーからも復帰できます。
- **完全終了**：通知領域のメニューで「終了」を選びます。

追従は `ChatGPT.exe` / `Codex.exe` のウィンドウが対象です。対象が前面のときに表示し、最小化時や他のアプリが前面のときには隠します。追従先がない場合は画面左下を使います。設定は Windows の `%APPDATA%\codex-usage-overlay\settings.json` に保存し、ログイン情報や残量は保存しません。

## 使用量の自動更新

標準は **1分ごと**です。メニューから 1・2・3・5分に変更できます。「更新」ボタンは即時取得します。スリープから復帰した際にも取得します。

OpenAI の [Codex app-server](https://github.com/openai/codex/tree/main/codex-rs/app-server) にローカルの標準入出力で接続します。`initialize` → `initialized` の後、`account/rateLimits/read` を読み取り、Codex の枠を選びます。

- `windowDurationMins` が `300` / `10080` の枠を5時間 / 7日間として表示します。
- 残り割合は `max(0, 100 − usedPercent)` です。回数やトークン数を推測しません。
- `resetsAt` は Windows のローカル日時で表示します。
- 未提供の期間・数値は `—` / 不明と表示します。
- 取得失敗時は前回の値と明示し、認証が失われた場合やアカウント変更時には消します。
- リセット時刻を過ぎただけで残量を100%には戻しません。

使用量の取得と、次の「アプリ自体の更新」は別です。

## 改善版の自動取得

v0.2 以降は **起動時と30分ごと**に、この GitHub リポジトリの `update.json` を確認します。新しい版があれば、自動で取得して準備します。準備ができるとパネルに「改善版を受信済み」と「再起動」が出ます。

**取得済みの改善版は次回起動時に適用**します。その場で切り替えたい場合は「再起動」を押してください。勝手に画面を閉じたり、作業中の Codex アプリを再起動したりはしません。ネットワーク不通でも現在の版を使えます。手動確認と自動取得のオン・オフも設定メニューにあります。

更新は `%APPDATA%\codex-usage-overlay\updates` の別フォルダに準備します。GitHub の固定の HTTPS URL・SHA-256・ファイル名・パッケージの識別情報を検証し、依存関係の準備と通信しないデモの起動確認に成功してから適用対象にします。同じ依存関係は再利用し、異なる場合はロックファイルに沿って取得します。ダウンロードや準備に失敗した版は適用しません。適用した版が起動直後に異常終了した場合はランチャーが旧版へ戻します。

プログラムは公開リポジトリ内のソースと `updates/<version>.json` に入ります。更新データに資格情報や利用データは含みません。GitHub へアクセスできない環境や、Windows のアプリ実行制限・セキュリティソフトにより起動確認できない環境では自動取得が完了しない場合があります。

## 認証・データ

認証の管理は公式 Codex CLI に任せます。このアプリはトークンを認証ファイルから取り出したり、独自の認証ストアへコピーしたりしません。会話の内容は読み取りません。使用量は表示するためにメモリ内で保持します。

画面は Node.js に直接アクセスできず、外部通信もできません。ログイン時には Codex が返す `https://auth.openai.com/` の認証 URL を既定のブラウザで開きます。アプリの改善版はメインプロセスが GitHub から取得します。Windows の PowerShell ヘルパーはウィンドウの位置と前面状態を読み取ります。

## 開発・配信

既存のチェックアウトを使用してください。クラウドタスクは隔離済みなので、別の Git worktree は不要です。

```sh
npm ci
npm run install:electron
npm test
npm run demo
npm run probe
```

`demo` は架空の値を表示し、ログインや通信をしません。`probe` は実際のログイン先の利用枠を取得し、5時間・7日間の両方を確認できなければ非ゼロで終了します。

GUI・更新ランチャーは次のコマンドで検証します。ステージ版は架空の次バージョンで更新選択を、ロールバックは意図的に起動失敗するテスト版で旧版への復帰を検証します。実アカウントには接続しません。

```sh
npm run smoke
npm run smoke -- --launcher
npm run smoke -- --staged-update
npm run smoke -- --rollback-update
```

Linux で画面がない場合、スモークランナーが Xorg の dummy ドライバーと `xdpyinfo` を使って一時的な画面を用意し、終了後に停止します。このクラウドの SUID サンドボックス制約では、**通信しないデモ検証限定**で上記コマンドに `--cloud-no-sandbox` を付けます。通常起動や Windows でこのフラグは使用しません。

依存関係を再インストールするクラウド用コマンド：

```sh
NODE_USE_ENV_PROXY=1 electron_config_cache=/workspace/.cache/electron npm --cache /workspace/.cache/npm ci
NODE_USE_ENV_PROXY=1 electron_config_cache=/workspace/.cache/electron npm run install:electron
```

TLS・パッケージ整合性・Electron のチェックサム検証は有効なままです。

### 今後の改善を配信する手順

1. コードを変更し、`npm version <新しいバージョン> --no-git-tag-version` でバージョンとロックファイルを更新します。
2. 自動テストとスモークテストを実行します。
3. `npm run publish:update` で検証用の更新データを生成します。
4. ソース・`update.json`・`updates/<version>.json` をコミットして `main` へ push します。

**一度配信したバージョンの更新データは上書きしません。** 内容を変える場合は次のバージョンにします。GitHub Actions にも Windows での検証・更新データ生成を登録しています。バージョンを上げたソースだけを push した場合、検証に通れば更新データを自動コミットします。検証や GitHub の権限設定で失敗した場合はそのジョブを確認してください。利用者側は再度 ZIP を取得する必要はありません。

### 検証の範囲

v0.1 は利用者の Windows で表示・使用量取得を確認しています。v0.2 の単体テスト、3サイズの実 Electron 表示、非表示・復帰、更新ランチャー・ステージ版・旧版への復帰は Linux クラウドで検証します。新しい位置調整・最小化・DPI・Windows での更新準備は実機検証も必要です。GitHub Actions は実行結果が確認できるまで成功済みとは扱いません。
